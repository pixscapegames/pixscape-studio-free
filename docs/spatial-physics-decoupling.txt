Spatial / physics separation
============================

The three geometries are independent authored sources on the same entity:
- PhysicsShapesComponent owns ordinary collision geometry in metres (Body + shapes).
- SpatialFootprintComponent owns a nonphysical circle: localOffsetXPx,
  localOffsetYPx, radiusPx (> 0) and altitude, all finite.
- SpatialRepresentationComponent owns static or animation asset/clip rectangles.
  Width/height are positive finite projected pixels. Rectangle x/y are projected
  pixel offsets from the resolved entity origin, not from the footprint.

The circle's local offset rotates with the resolved owner pose. Its radius is
unaffected by visual scale, origin and flip. The rectangle remains axis-aligned
in projected pixels; visual scale/rotation do not resize it. Both follow entity
translation, including resolved Game Object placement. Render display offsets
are applied once by the existing render consumers. No world-frozen geometry or
silent compensation of authored offsets is introduced.

Shadow pivot offsets remain relative to the resolved footprint, in projected
pixels. This is the existing shadow orientation anchor, distinct from rectangle
placement. Moving the footprint changes this logical pivot anchor and the circle
used for spatial relationships, but not the rectangle's resolved position or
alpha mapping. A rectangle edit never changes footprint data. Sorting rules and
wall continuations retain their existing geometric meaning.

SpatialEntityFacade.enable and Studio Spatial Actor activation create the circle
and representation data without adding or editing physics. setFootprint validates
and publishes spatial data directly; no PhysicsService footprint mutation API,
derived collision source, automatic copy, uniqueness rule or compiler branch
remains. Editing/removing spatial state never recompiles or edits collisions.
Editing/removing collisions never edits spatial state. Native Box2D remains pose
authority for simulated bodies and remains a distribution dependency.

Tiled spatialBlockId collisions are a separate, preserved mechanism. Their
optional collision checkbox requires scene Physics for creation; existing linked
collisions can still be removed/restored. Body restoration prepares the complete
collision candidate before publishing the restored Body, then restores joints.

Persistence
-----------
New scenes use schema 6; Game Object definitions/fragments use schema 5. The
unpublished old footprint-relative format and removed useSpatialFootprint field
are rejected (including false), with no migration or fallback. Older schema-3/4
Tiled-only conversion remains supported; old actor spatial data is rejected before
replacing the current scene. Compiled/native physics caches are never authored.
Scene save/export, clipboard, Game Object capture/spawn copy each source separately.
Static and per-animation/clip rectangles retain their distinct authored values.

Studio
------
Spatial works without scene Physics on supported sprite/animation spatial layers.
Selecting one spatial actor in Normal mode exposes all six handles directly.
Footprint center/radius use a cyan cross/circle, rectangle center/width/height
use green squares, and the footprint-relative shadow pivot uses a purple target.
White hover and yellow drag rings mark the single pending/active handle.
The nearest handle within nine UI units wins, independently of world zoom.
Exact distance ties use this stable order: shadow pivot, rectangle center,
rectangle width, rectangle height, footprint center, footprint radius.
The target stays fixed until release/cancellation, even across other handles.
Handles stay at their true anchors: zoom separates nearby handles; exact
coincidence can be resolved by moving the first geometry slightly to reach the
next. No automatic handle displacement, exclusive selector, or extra mode.
Physics edit mode owns collision gestures, and spatial handles cannot intercept
them. Picking uses the existing native Stage overlay, without a second global loop.

Circle center dragging edits its owner-local offsets; the radius handle edits its
positive radius. Numeric fields follow the preview. A completed gesture produces
one history command; Escape and canceled native touch focus restore the snapshot.
Rectangle/pivot gestures retain their history lifecycle. Shift retains fine motion.
Radius and rectangle dimensions require finite positive values; offsets/altitude/
pivot allow finite signed values. Invalid spatial input retains the standard VisUI
red border and text, publishes nothing and creates no history. Enter/focus loss
commit valid input; Escape restores uncommitted input from the model.

Scene Physics disable remains a confirmed complete purge of physics, preserving
spatial data. Cancel preserves physics. No dormant physics state is introduced.
Ordinary collisions retain geometry/material editing, duplication and deletion;
Tiled-linked collisions retain their existing restrictions.

Limits
------
Only circles and same-entity owner/representation are delivered. No root-to-child
spatial binding, rectangular footprint, new hierarchy, collision engine or action
composition is introduced. Additional animation clips require authored rectangles.
